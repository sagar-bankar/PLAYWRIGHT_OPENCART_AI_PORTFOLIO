PLAYWRIGHT_OPENCART_AI_PORTFOLIO

Playwright + TypeScript Hybrid Test Automation Framework

Project Name: PLAYWRIGHT_OPENCART_AI_PORTFOLIO

A professional-grade hybrid test automation framework built with Playwright and TypeScript, covering browser UI flows, REST API contracts and database verification in one layered codebase. It follows the Page Object Model, exposes typed fixtures, validates responses against JSON schemas, and produces HTML, JUnit and Allure reports from a single run — executed on both GitHub Actions and Jenkins.

48 Tests in CI run
49 Total specs
8 Page Objects
26 API Routes

Tools & Technologies

  • Language: TypeScript (Node.js)
  • Test Runner: Playwright Test v1.65
  • Design Pattern: Page Object Model + custom fixtures
  • API Layer: Playwright request fixture
  • Schema Validation: AJV against JSON schemas
  • Database: MySQL via mysql2
  • Reporting: Playwright HTML, JUnit XML, Allure, custom reporter
  • Test Data: Faker, CSV parsing, Excel (xlsx)
  • Config: dotenv environments
  • Accessibility: @axe-core/playwright
  • Generative AI: GitHub Copilot, Playwright MCP, Claude Code, Codex, Command Code, OpenRouter, Caveman
  • CI/CD: GitHub Actions & Jenkins
  • Containerisation: Docker & Docker Compose

Generative AI & GitHub Copilot in Testing

Generative AI is used as an assisted-engineering layer across the test lifecycle, not as an autopilot. The emphasis is on prompt engineering skill — structuring context, intent, constraints and expected outcomes so the coding agent produces reviewable output that fits this framework — combined with AI-agent workflows that cover design, authoring, debugging and review.

AI Toolchain

  • GitHub Copilot — inline completions, chat-driven refactoring and test scaffolding inside the editor.
  • Playwright MCP — live browser and API analysis so locators and endpoints are verified against the real application, never invented.
  • Claude Code, Codex, Command Code — agentic coding sessions for multi-file work: new Page Objects, API route + schema + spec triples, and DB specs.
  • OpenRouter — single gateway for model access across those agents, so the same context file drives whichever model is in use.
  • Caveman — used throughout development to cut token cost: /caveman-commit for one-line conventional commit messages, /caveman-review for terse per-line findings, and compressed Playwright failure output so long test logs cost less to read. Code, paths and error text stay verbatim.
  • Shared context file — playwright_mcp_context.md acts as the single source of truth for every agent.
Project evidence: playwright_mcp_context.md in the repository defines how agents must analyse the app, order dependencies, reuse existing components, verify selectors through live execution and avoid hallucinated locators, endpoints and schemas. Different agents produce consistent output because they work from the same contract.
Where to verify Caveman: /caveman-commit leaves its trace in the repository itself — the conventional one-line commit messages in the git history are its output. /caveman-review and log compression act on agent sessions instead, so they reduce cost rather than producing committed files.

Prompt Engineering Approach

  • Context first: Supply the framework layout, Page Object conventions, fixture usage and locator strategy before requesting code.
  • Intent and scope: State the single behaviour under test, the layer it belongs to (web, API, DB) and the file it should live in.
  • Constraints: Specify TypeScript typing, tag conventions, accessible locators, assertion style and what must not be changed.
  • Expected output: Define acceptance in terms of passing assertions and readable failures rather than "make it work".
  • Iterate with feedback: Treat the first response as a draft — refine with the actual error, trace or review comment.

Copilot Workflows by Stage

  • Test design: Turn requirements into positive, negative and boundary scenarios for the OpenCart UI and FakeStore API.
  • Page Object authoring: Draft locators and action methods that follow the existing encapsulation and accessible-locator patterns.
  • Test implementation: Generate spec scaffolding and fixtures-aware test bodies aligned with current project structure.
  • API validation: Build request flows and JSON schema assertions for authentication, products and carts.
  • Failure analysis: Interpret Playwright errors and traces, identify likely root causes and propose focused fixes.
  • Test review: Check assertion strength, edge-case coverage and maintainability before execution.
  • Documentation: Summarise framework decisions and setup steps for the repository README and this portfolio.
Human review: Every Copilot suggestion is verified against requirements, project patterns and actual test results. Assertions are never accepted on trust, and the tester owns the final code, validation and root-cause decisions.

Running the Suite

Suites are selected by Playwright tag through npm scripts, so the same commands work locally and in CI.

Setup

$ npm install
$ npx playwright install
$ cp .env.example .env          # base URL, FakeStore endpoint, MySQL credentials

Scripts from package.json

Command Runs
npm run test:webAll UI specs — --grep @web
npm run test:apiAll API specs — --grep @api
npm run test:sanitySmoke subset — --grep @sanity
npm run test:regressionFull regression set — --grep @regression
npm run test:e2eEnd-to-end journeys — --grep @e2e
npm run test:datadrivenCSV / Excel driven login — --grep @datadriven
npm run test:masterEverything tagged @master
npm run test:sanity:debugSanity subset in Playwright Inspector — --debug
npm run test:master:headedHeaded sanity run — --headed

Direct Playwright usage

$ npx playwright test --grep @api --headed   # tag filter at runtime
$ npx playwright test tests/web/validLogin.spec.ts
$ npx playwright test --grep-invert "@db"    # CI skips MySQL spec
$ npx playwright show-report                # open last HTML report

CI/CD Integration

Jenkins

  • Declarative pipeline, parameters for suite, browser and mode
  • Publishes JUnit, Allure and two HTML reports
  • Archives reports, screenshots, videos and traces
  • Post-build email with job, build, status, suite, browser and report links

GitHub Actions

  • Manual dispatch with the same three inputs
  • Runs on windows-latest with Node LTS
  • Uploads Playwright, custom and Allure reports
  • 30-day artifact retention
Environment note: the @db spec needs a MySQL instance reachable at DB_HOST:DB_PORT with the openshop schema. CI skips it with --grep-invert '@db'; it runs locally where the database is available.
